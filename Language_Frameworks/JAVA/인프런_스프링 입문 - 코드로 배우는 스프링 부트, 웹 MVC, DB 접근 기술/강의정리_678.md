# SECTION7 스프링 DB 접근기술

- JDBC : SQL과 Application 서버를 연결해주는 것임
- JDBC Template : 스프링이 제공함. 중복을 제거해서 템플릿으로 제공. SQL을 편리하게 날릴 수 있게 함
- JPA : SQL을 jpa가 직접 만들어서 쿼리를 날림 저장과 관리
- 스프링 데이터 JPA : JPA를 편리하게 쓸 수 있도록 감싼 기술

## 순수 JDBC

- build.gradle 파일에 아래의 라이브러리 추가

```java
implementation 'org.springframework.boot:spring-boot-starter-jdbc'
runtimeOnly 'com.h2database:h2'
```

- 자바는 기본적으로 db와 연결하려면 jdbc driver가 꼭 있어야한다
- h2는 db 클라이언트이다.

- 그리고 이것을 레포지토리가 주입받아야한다.
- connection과 close는 datasource utils를 통해서 해야한다.

## 스프링 통합 테스트

- @SpringBootTest : 스프링 컨테이너와 테스트를 함께 실행한다
- @Transactional : 테스트 케이스에 이 애노테이션이 있으면, 테스트 시간 전에 트랜잭션을 시작하고, 테스트 완료 후에 항상 롤백을 한다. 이렇게 하면 DB에 데이터가 남지 않으므로 다름 테스트에 영향을 주지 않는다.

## Jdbc Template

- template method pattern을 사용하여 기존의 중복되된 코드를 줄임
- TEST는 정말 중요하다. 테스트코드를 잘 짜는 것이 중요하다
- 작은 버그 하나가 엄청난 피해로 돌아온다.
- 개발을 잘 하는 사람일수록 테스트코드, 케이스에 꼼꼼하다
- 아래는 template을 쓰는 얘시이다.

# JPA

- Jebc, Jdbc template 모두 개발자가 결국 sql을 작성해야했다.
- JPA는 SQL도 직접 만들어서 실행해준다
- 이를 통해 SQL과 데이터 중심의 설계에서 객체 중심의 설계로 패러다임을 전환할 수 있다.
- Jpa는 interface이고 hibernate등등은 구현체이다.
- 대부분 jpa interface에 hibernate 구현체를 사용한다.
- 구현은 여러 업체가 한다. 업체마다 쓰기 편하거나 성능이 좋거나 등등 있다.
- Jpa는 orm(object relational mapping) 중 하나이다.

- jpa는 모든 데이터 변경이 transaction 안에서 이루어져야 한다
